# 安全模型

本文说明 `@leisureyu/dsh-smart-dl` 把「不可信输入」挡在哪几层，以及为什么每一层都不能省。
每一层都对应一次**实测复现过的**真实缺陷，不是理论推演。

## 威胁模型

`smart_download` 的 `url` 不是用户手输的常量，而是模型从网页、issue、release 页面里读到的
字符串。这意味着调用方无法保证 URL 的协议、路径、文件名是善意的。同时，下载会真的写磁盘、
真的起子进程、真的走网络出口，因此三类风险必须单独处理：

| 风险 | 触发方式 | 后果 |
| --- | --- | --- |
| 本地文件被读走 | `file://` 之类协议 | 把 `/etc/passwd`、`win.ini` 复制到工作目录 |
| 写到工作目录之外 | URL 路径穿越（`..%2F` 等） | 覆盖任意可写路径 |
| 拿到错误内容却报成功 | 服务器/镜像/代理异常 | 用户以为下载成功，产物是坏的 |

## 四层防护

### 第一层：协议白名单（`src/url.ts`）

`SUPPORTED_PROTOCOLS = ['http:', 'https:']`，`checkDownloadUrl()` 在**任何网络请求之前**执行。
解析失败或不匹配就抛错，不进入探测、不进入下载。

> `0.4.1` 实测：`file:///C:/Windows/win.ini` 交给 `curl` 会被接受，并且**成功把本地文件
> 复制**到了目标路径。探测阶段对 `file://` 当然会失败，问题恰恰出在「探测失败 → 回退
> curl」这条看似安全的兜底路径上。白名单是唯一能堵住它的地方。

这层还顺带处理了「URL 解析不出」的情况：`checkDownloadUrl` 返回 `{ ok: false, reason }`，
reason 里带上原始输入（`JSON.stringify` 转义），便于排查而不会把内容当格式串用。

白名单必须覆盖 `mirror` 参数，光管 `url` 不够。`mirror` 在 `applyMirror` 里是**字符串前缀**，
拼接后整串的 scheme 由前缀决定；前缀若是 `file://`，后半段合法的 http 地址会退化成 query，
整串仍是合法的 `file:` URL。

> `1.0.0` 实测（修复前）：`applyMirror('http://example.com/a.bin', 'file:///C:/Windows/win.ini?x=')`
> 得到 `file:///C:/Windows/win.ini?x=/http://example.com/a.bin`，交给 `curl -L --fail` 退出码
> 为 0，成功把本机 `win.ini`（92 字节）复制到目标路径。`javascript://`、`data://` 同样能过。
> 修复后 `applyMirror` 先判前缀本身是否 http(s)，不是就原样返回原始 URL，
> `test/mirror.test.ts` 有正向用例断言返回值就是原始 URL。

### 第二层：文件名净化（`src/url.ts`）

未传 `output` 时，文件名从 URL 推导。推导顺序刻意做了两次切分：

1. 取 `pathname` 的最后一段；
2. `decodeURIComponent()`；
3. **再按 `[\\/]+` 切一次，只取最后一段**；
4. `sanitizeFilename()`：替换 `<>:"|?*\` 与控制字符 → 去掉首尾空白与点 →
   规避 Windows 保留设备名 → 按 200 code unit 截断（尽量保住扩展名）→ 空则回落 `download`。

第 3 步是必须的：URI 解码会把 `%2F` 还原成 `/`，**凭空造出目录层级**。

> `0.4.1` 实测：`http://host/..%2F..%2F..%2Fescaped.txt` 解出 `../../../escaped.txt`，
> 未指定 `output` 时文件被写到了**当前工作目录之外**（确认写入成功）。
> `0.4.2` 起在解码后再切分，`test/url.test.ts` 与 `test/execute.test.ts` 各有一条用例
> 断言「推导结果必定是单段文件名」且「实际落盘不逃出当前目录」。

净化在 Linux 上也替换 Windows 非法字符：同一个 URL 在两个平台上必须推导出同一个名字，
否则「先解析路径、后落盘」的调用方会看到不一致的结果。

### 第三层：续传指纹（`src/resume.ts`）

「服务器支持 Range」不等于「本地半包是同一个资源的合法前缀」。`curl -C -` 与 `aria2 -c`
都**只看本地文件长度**，不看远端有没有变。

> `0.6.0` 用真实 curl 8.13.0 与随包 aria2 1.37.0 在 127.0.0.1 上实测：
>
> | 场景 | `curl -C -` | `aria2 -c` |
> | --- | --- | --- |
> | 远端变大 400B → 1000B（同源） | exit 0，正确 | exit 0，正确 |
> | 远端变小 400B → 200B | **exit 0，仍是 400B** | **exit 0，仍是 400B** |
> | 远端等长但内容变了 | **exit 0，旧内容** | **exit 0，旧内容** |
> | 服务器忽略 Range | exit 33（报错） | exit 0，正确 |
>
> 前三行是「退出码 0 且文件是错的」，用户拿到的是看起来成功、实际错误的产物。

因此续传前 `planResume()` 会按顺序判定：本地无文件 / 远端长度未知 / 本地比远端长 /
旁车指纹（`<output>.part.json`）里的 ETag 或 Last-Modified 不一致 / 旁车长度与远端不一致 ——
任何一种「无法证实同源」都**删掉本地半包全量重下**，并同时清掉该半包的 aria2 控制文件
（`<output>.aria2`，留着它 aria2 会按旧进度继续）。

指纹只比长度挡得住前两行，挡不住「等长但内容变了」，这就是必须有旁车指纹的原因。
指纹在下载成功时清除、失败或中断时保留（失败时保留才有下次可比的基准）。

### 第四层：落盘字节数校验（`src/verify.ts`）

下载工具的退出码 0 只代表「它自己认为完成了」。`assertIntegrity()` 在子进程成功返回后
比对**落盘字节数**与**远端声明长度**。

> `0.7.0` 实测：服务器用 chunked 只发 1MB 就干净断开、而 HEAD 声明 4MB 时，
> 随包 aria2 1.37.0 的退出码是 **0**、「Download Results」里写着 `OK`，落盘只有 1MB；
> 同一场景 `curl` 也是 exit 0。没有任何非零退出码可供判断。

校验有两条明确的**跳过**分支，且跳过是显式的：

| 情形 | 结论 | 原因 |
| --- | --- | --- |
| 远端未声明长度 | `skipped: remote-length-unknown` | 没有基准可比 |
| 服务器返回了压缩编码 | `skipped: content-encoded` | 压缩后长度与落盘字节数不可比 |
| 本地文件读不到 | `mismatch` | exit 0 却没文件，本身是异常 |
| 字节数不等 | `mismatch` | 明确报错，绝不返回 success |

跳过会把固定文案写进 `SmartDownloadResult.verifySkipped` 与进度终态，模型与用户都能看到
「这次没有做字节数校验」。`0.9.0` 之前跳过与通过共用 `{ kind: 'ok' }`，两者在返回值里长得
一模一样 —— 这正是本项目反复出问题的静默失败形态。

压缩编码那条是防**误报**而不是防漏报：探测已强制 `accept-encoding: identity`，但仍有服务器
无视它。`0.7.0` 实测 5000 B 的 body 在默认探测下报 41 B（gzip 后），若不跳过，任何支持 gzip
的服务器都会让正确下载被判成损坏。

## 输出路径与覆盖语义

- 写入 `output` 指定的路径；父目录不存在时创建（`mkdir -p`）。
- **不删除**用户已有的文件，`output` 之外的文件一律不动。唯一的例外是第三层里那个被判定
  「无法证实同源」的本地半包 —— 它会被删除，理由是续传它必然产出错误内容。判定依据会写进
  返回结果的 `reason`（如 `ETag 变化（"v-old" → "v-new"），资源已更新，全量重下`）。
- aria2 一律带 `--allow-overwrite=true`：aria2 默认遇到同名文件不覆盖，而是另存为
  `f.1.bin`，而插件返回的 `path` 仍指向旧文件 —— 一次静默的路径错位（`0.6.0` 修复）。

## 网络出站

- 只访问调用方传入的 URL（启用镜像时为「镜像前缀 + 原始 URL」），不访问其他地址、无遥测。
- 探测默认 5 秒超时，且与调用方的 `AbortSignal` 合并（`AbortSignal.any`）。
- **镜像是第三方中转**：请求内容会经过镜像服务器。文档与 README 都提醒不要用它下载含敏感
  信息的文件；插件无法验证镜像返回的内容是否忠实于源站（这正是第四层字节数校验存在的原因
  之一 —— 镜像返回一个 200 的错误页时，只有校验能拦下）。

## 子进程

- 启动随包 `aria2c` 或系统 `curl`，均以 `windowsHide: true` 启动，不弹控制台窗口。
- 参数以数组形式传给 `spawn`，不经 shell，因此 URL 里的字符不会被 shell 解释。
- 取消时先 `SIGTERM`，1 秒内未退出则 `SIGKILL` 兜底；兜底对**所有平台**生效
  （`0.9.0` 之前只对 Windows 生效，POSIX 上进程忽略 `SIGTERM` 会让调用永久挂住）。
- aria2 的 `-o` 只接受文件名、目录用 `-d` 传，避免把路径拼进单个参数。

## 权限清单

| 行为 | 说明 |
| --- | --- |
| 网络出站请求 | 仅 `http` / `https`；`HEAD` / `Range` 探测与实际下载；只访问传入的 URL |
| 写入下载文件 | `output` 路径或按 URL 推导的单段文件名；不写工作目录之外 |
| 读取进度文件 | `download_status` 与 `/api/smartdl.status` 只读扫描，不写、不联网 |
| 写进度文件 | 两条轨道（见 README「进度上报」）；目录不可写时静默跳过，不影响下载 |
| 子进程 | 随包 `aria2c` 或系统 `curl`；`windowsHide`；响应 `AbortSignal` |
| 读取环境变量 | 仅 `DSH_PROGRESS_DIR`、`DSH_DOWNLOAD_PROGRESS_DIR`、`DSH_HOME` |

**不需要**的权限：不读取 DSH 会话内容、不访问凭证或密钥、不修改 DSH 配置（`cordis.patch.yml`
由 DSH 自身在安装时应用）、无遥测与联网上报。

## 已知边界

- 不做内容哈希校验（不比对 sha256）。远端声明的长度本身也可能是错的或恶意的，
  此时长度校验会通过。真正的内容校验需要远端提供摘要，本插件不假设这一点。
- 进度文件里含输出文件名与 URL 推导出的路径，会落在 `.dsh-progress/` 与会话目录下，
  与其他 DSH 插件共享同一套可见性规则。
- 随包 `aria2c.exe` 未做代码签名，可能触发杀毒软件的启发式告警，见
  [TROUBLESHOOTING.md](./TROUBLESHOOTING.md)。

## 漏洞报告

请通过仓库的 private security advisory 或 issue 报告，不要在公开渠道披露可利用细节。
报告时请附上复现步骤与实际输出（尤其是「退出码 0 但结果不对」这一类）。
