# 安全模型

本文说明 `@leisureyu/dsh-smart-dl` 把「不可信输入」挡在哪几层，以及为什么每一层都不能省。
每一层都对应一次**实测复现过的**真实缺陷，不是理论推演。

## 威胁模型

`smart_download` 的 `url` 不是用户手输的常量，而是模型从网页、issue、release 页面里读到的
字符串。这意味着调用方无法保证 URL 的协议、路径、文件名是善意的。同时，下载会真的写磁盘、
真的起子进程、真的走网络出口，因此三类风险必须单独处理：

| 风险 | 触发方式 | 后果 |
| --- | --- | --- |
| 本地文件被读走 | `file://` 之类协议 | 把 `/etc/passwd`、`win.ini` 复制到工作目录 |
| 写到工作目录之外 | URL 路径穿越（`..%2F` 等） | 覆盖任意可写路径 |
| 拿到错误内容却报成功 | 服务器/镜像/代理异常 | 用户以为下载成功，产物是坏的 |

## 五层防护

### 第一层：协议白名单（`src/url.ts`）

`SUPPORTED_PROTOCOLS = ['http:', 'https:']`，`checkDownloadUrl()` 在**任何网络请求之前**执行。
解析失败或不匹配就抛错，不进入探测、不进入下载。

> `0.4.1` 实测：`file:///C:/Windows/win.ini` 交给 `curl` 会被接受，并且**成功把本地文件
> 复制**到了目标路径。探测阶段对 `file://` 当然会失败，问题恰恰出在「探测失败 → 回退
> curl」这条看似安全的兜底路径上。白名单是唯一能堵住它的地方。

这层还顺带处理了「URL 解析不出」的情况：`checkDownloadUrl` 返回 `{ ok: false, reason }`，
reason 里带上原始输入（`JSON.stringify` 转义），便于排查而不会把内容当格式串用。

白名单必须覆盖 `mirror` 参数，光管 `url` 不够。`mirror` 在 `applyMirror` 里是**字符串前缀**，
拼接后整串的 scheme 由前缀决定；前缀若是 `file://`，后半段合法的 http 地址会退化成 query，
整串仍是合法的 `file:` URL。

> `1.0.0` 实测（修复前）：`applyMirror('http://example.com/a.bin', 'file:///C:/Windows/win.ini?x=')`
> 得到 `file:///C:/Windows/win.ini?x=/http://example.com/a.bin`，交给 `curl -L --fail` 退出码
> 为 0，成功把本机 `win.ini`（92 字节）复制到目标路径。`javascript://`、`data://` 同样能过。
> 修复后 `applyMirror` 先判前缀本身是否 http(s)，不是就原样返回原始 URL，
> `test/mirror.test.ts` 有正向用例断言返回值就是原始 URL。

**这一层同时意味着：本插件不支持 FTP / SFTP / BitTorrent**（`magnet:` 也不在
`SUPPORTED_PROTOCOLS` 里）。理由是「放开之后会发生什么」，逐条核对见
[PLAN-P2-PLATFORM.md](./PLAN-P2-PLATFORM.md) §B（核对时间 2026-10-12）：

| 协议 | 为什么不做 |
| --- | --- |
| **FTP** | 五层防护里只剩第五层（调用方提供的 `sha256` / `checksum`）有效，而它是**可选参数** —— 不传就没有任何内容校验。FTP 协议本身不提供内容摘要，长度是唯一弱信号，而它挡不住「等长但内容不同」（正是第四层存在的原因）。此外 `user:password@host` 会把**明文凭证**放进 URL，且 FTP 默认明文传输。 |
| **SFTP** | 与 FTP 同类问题（无完整性保证、凭证面、权限清单），且额外引入 `libssh2` 依赖面 —— 现有 aria2 构建是 `--without-libssh2`。 |
| **BitTorrent** | **一层防护都复用不了**：BT 的「文件名」来自 torrent 元数据而非 URL（且可能是多文件），续传由分片状态决定而非 ETag/Last-Modified，长度来自元数据而非远端声明。更关键的是威胁模型：`magnet:` 会让客户端连 DHT 网络、交换 peer 列表、监听入站端口、并默认**上传（做种）** —— 插件的行为会从「访问调用方给的那一个 URL」变成「访问一张由陌生人给出的、不断变化的 peer 表」，本文末尾的权限清单因此无法维持。 |

**因此这不是「暂时没做」的功能缺口，而是一条刻意划定的边界。** 如果未来要放开，
正确形态不是「在 `smart_download` 里加一个协议分支」，而是**独立的工具 + 独立的权限与
威胁模型文档**（`smart_download` 的五层防护与 README 的契约表都绑定了一组 HTTP 特有的
前提，在同一函数里按协议分支会让每条断言都要同时覆盖两种语义）。

### 第二层：文件名净化（`src/url.ts`）

未传 `output` 时，文件名按固定优先级推导：`Content-Disposition` → 查询串
`?filename=` / `?file=` → URL 路径末段。**这三者都是不可信输入**：

- 服务器可以在 `Content-Disposition` 里返回 `filename="../../x"`；
- RFC 5987 的 `filename*=UTF-8''..%2F..%2Fx` 同样由服务器控制；
- 查询串里的 `filename` / `file` 也是调用方 URL 的一部分，可能来自网页或 issue。

因此三者最终都必须经过同一个 `sanitizeFilename()`，得到**单段文件名**。URL 路径这条
还额外做了两次切分：

1. 取 `pathname` 的最后一段；
2. `decodeURIComponent()`；
3. **再按 `[\\/]+` 切一次，只取最后一段**；
4. `sanitizeFilename()`：替换 `<>:"|?*\` 与控制字符 → 去掉首尾空白与点 →
   规避 Windows 保留设备名 → 按 200 code unit 截断（尽量保住扩展名）→ 空则回落 `download`。

第 3 步是必须的：URI 解码会把 `%2F` 还原成 `/`，**凭空造出目录层级**。

> `0.4.1` 实测：`http://host/..%2F..%2F..%2Fescaped.txt` 解出 `../../../escaped.txt`，
> 未指定 `output` 时文件被写到了**当前工作目录之外**（确认写入成功）。
> `0.4.2` 起在解码后再切分，`test/url.test.ts` 与 `test/execute.test.ts` 各有一条用例
> 断言「推导结果必定是单段文件名」且「实际落盘不逃出当前目录」。

显式传入的 `output` 永远优先，不做任何猜测；它允许带目录（这是调用方的明确意图），
但文件名部分仍应视为调用方输入，不应由服务器控制。

净化在 Linux 上也替换 Windows 非法字符：同一个 URL 在两个平台上必须推导出同一个名字，
否则「先解析路径、后落盘」的调用方会看到不一致的结果。

### 第三层：续传指纹（`src/resume.ts`）

「服务器支持 Range」不等于「本地半包是同一个资源的合法前缀」。`curl -C -` 与 `aria2 -c`
都**只看本地文件长度**，不看远端有没有变。

> `0.6.0` 用真实 curl 8.13.0 与随包 aria2 1.37.0 在 127.0.0.1 上实测：
>
> | 场景 | `curl -C -` | `aria2 -c` |
> | --- | --- | --- |
> | 远端变大 400B → 1000B（同源） | exit 0，正确 | exit 0，正确 |
> | 远端变小 400B → 200B | **exit 0，仍是 400B** | **exit 0，仍是 400B** |
> | 远端等长但内容变了 | **exit 0，旧内容** | **exit 0，旧内容** |
> | 服务器忽略 Range | exit 33（报错） | exit 0，正确 |
>
> 前三行是「退出码 0 且文件是错的」，用户拿到的是看起来成功、实际错误的产物。

因此续传前 `planResume()` 会按顺序判定：本地无文件 / 远端长度未知 / 本地比远端长 /
旁车指纹（`<output>.part.json`）里的 ETag 或 Last-Modified 不一致 / 旁车长度与远端不一致 ——
任何一种「无法证实同源」都**删掉本地半包全量重下**，并同时清掉该半包的 aria2 控制文件
（`<output>.aria2`，留着它 aria2 会按旧进度继续）。

指纹只比长度挡得住前两行，挡不住「等长但内容变了」，这就是必须有旁车指纹的原因。
指纹在下载成功时清除、失败或中断时保留（失败时保留才有下次可比的基准）。

### 第四层：落盘字节数校验（`src/verify.ts`）

下载工具的退出码 0 只代表「它自己认为完成了」。`assertIntegrity()` 在子进程成功返回后
比对**落盘字节数**与**远端声明长度**。

> `0.7.0` 实测：服务器用 chunked 只发 1MB 就干净断开、而 HEAD 声明 4MB 时，
> 随包 aria2 1.37.0 的退出码是 **0**、「Download Results」里写着 `OK`，落盘只有 1MB；
> 同一场景 `curl` 也是 exit 0。没有任何非零退出码可供判断。

校验有两条明确的**跳过**分支，且跳过是显式的：

| 情形 | 结论 | 原因 |
| --- | --- | --- |
| 远端未声明长度 | `skipped: remote-length-unknown` | 没有基准可比 |
| 服务器返回了压缩编码 | `skipped: content-encoded` | 压缩后长度与落盘字节数不可比 |
| 本地文件读不到 | `mismatch` | exit 0 却没文件，本身是异常 |
| 字节数不等 | `mismatch` | 明确报错，绝不返回 success |

跳过会把固定文案写进 `SmartDownloadResult.verifySkipped` 与进度终态，模型与用户都能看到
「这次没有做字节数校验」。`0.9.0` 之前跳过与通过共用 `{ kind: 'ok' }`，两者在返回值里长得
一模一样 —— 这正是本项目反复出问题的静默失败形态。

压缩编码那条是防**误报**而不是防漏报：探测已强制 `accept-encoding: identity`，但仍有服务器
无视它。`0.7.0` 实测 5000 B 的 body 在默认探测下报 41 B（gzip 后），若不跳过，任何支持 gzip
的服务器都会让正确下载被判成损坏。

### 第五层：调用方给的摘要（`src/hash.ts`，`1.2.0` 起）

第四层只能证明「字节数对」，证明不了「内容是同一份」——等长的替换、镜像返回的另一个
版本、被投毒的同名文件，长度全都一致。第五层由调用方把**官方文档里印着的摘要**传进来，
落盘后流式计算实际摘要并比对。

它同时补上了第四层「跳过」时的空白：哈希不依赖任何远端信息，因此远端未声明长度、或
远端返回压缩编码时，长度校验被迫跳过，哈希仍然给出确定结论（此时返回值里不会出现
`verifySkipped`，而是出现 `sha256` 或 `checksum` + `checksumAlgorithm`）。

`1.5.0` 起支持四种算法，入参分两条路径：

| 入参 | 接受什么 | 返回什么 |
| --- | --- | --- |
| `sha256` | 只接受 SHA-256（裸 hex / `sha256:` / `SHA256(...)` / SRI） | 只返回 `sha256` |
| `checksum` | MD5 / SHA-1 / SHA-256 / SHA-512；裸 hex 按长度识别，也接受前缀与 `sha256-` / `sha512-` 的 SRI | 返回 `checksum` + `checksumAlgorithm` |

两者**同时给出会在下载前拒绝**：两个摘要代表两种真相，插件不替调用方挑一个。带前缀时
长度必须与算法匹配（`md5:<64位>` 会被拒绝，不会悄悄按 SHA-256 算）。

**算法强度**：MD5 / SHA-1 仅用于兼容老文档，不能抵抗刻意构造的碰撞；需要防篡改时用
SHA-256 / SHA-512。插件不做「摘要从哪来」的判断，只做「内容是否等于这个摘要」。

| 情形 | 结论 |
| --- | --- |
| 摘要合法且一致 | `ok`，返回值带对应的摘要字段 |
| 摘要不一致 | 抛错，**保留**旁车指纹 |
| 文件读不到 | 抛错，文案与「不一致」**不同**（两者不能长得一样） |
| 摘要写法不合法 | 在**下载开始前**拒绝，不白下一遍 |

它**不能**防的是：调用方自己传了一个错误的摘要（那会把好文件判成坏文件），或者官方
文档本身就给了错摘要。插件不做「摘要从哪来」的判断，只做「内容是否等于这个摘要」。

### 请求头注入（`src/headers.ts`，`1.2.0` 起）

`userAgent` / `referer` / `headers` 最终会进子进程命令行，因此有两道收紧：

1. **头值含 CR / LF / NUL 或其余 C0 控制字符（制表符除外）一律拒绝**。头值里的换行可以让
   调用方凭空往请求里塞新头甚至新请求 —— 这是请求头注入，与 URL 里的换行同一类问题。
2. **插件自身管理的头不允许覆盖**：`Range` / `Accept-Encoding` / `Content-Length` / `Host`
   与连接级头（`Connection` / `Keep-Alive` / `Transfer-Encoding` / `TE` / `Trailer` /
   `Upgrade` / `Proxy-Authorization` / `Proxy-Connection`）。它们各自承载着探测 / 续传 /
   校验的既有语义，被覆盖会**静默**改变行为（例如把 `Accept-Encoding` 改成 gzip，会让
   第四层校验对任何支持压缩的服务器 100% 误报）。

> **凭证会出现在进程命令行里。** 头是以 `spawn` 的参数数组传递的（不经 shell，因此没有
> shell 注入面），但在同机其他进程看来，`--header=Authorization: Bearer …` 是可见的。
> 不要把长期凭证写进 `headers`，也不要把它交给不可信的镜像。

## 输出路径与覆盖语义

- 写入 `output` 指定的路径；父目录不存在时创建（`mkdir -p`）。
- **覆盖语义由 `ifExists` 决定**：
  - `overwrite`（默认）会**替换 / 续写**同名目标文件，这是破坏性的，且不提供自动备份；
  - `skip` 不碰已有文件，只做探测（有摘要时校验已有文件），返回 `skipped: true`；
  - `rename` 只写新的 `name (n).ext`，绝不覆盖已有文件，并禁用续传。
- `output` 之外的文件一律不动。唯一的例外是第三层里那个被判定「无法证实同源」的本地
  半包：它会被删除，理由是续传它必然产出错误内容。删除时同时清掉该输出对应的
  `.aria2` 控制文件，避免 aria2 按旧进度继续。判定依据会写进返回结果的 `reason`
  （如 `ETag 变化（"v-old" → "v-new"），资源已更新，全量重下`）。
- 失败时 `.part.json` 旁车指纹**保留**，作为下一次续传的比对基准。
- aria2 一律带 `--allow-overwrite=true`：aria2 默认遇到同名文件不覆盖，而是另存为
  `f.1.bin`，而插件返回的 `path` 仍指向旧文件 —— 一次静默的路径错位（`0.6.0` 修复）。

## 网络出站

- 只访问调用方传入的 URL（启用镜像时为「镜像前缀 + 原始 URL」），不访问其他地址、无遥测。
- 例外只有一处：`mirror: "auto"` 时，候选镜像地址也会被**并发 HEAD 探测**一遍（每个同样
  5 秒超时，且与调用方的 `AbortSignal` 合并）。这是「必须先证实同源才采用」的必要代价，
  且必须显式传 `auto` 才会发生 —— 默认不启用，候选表也可用 `DSH_SMARTDL_MIRRORS` 收紧。
- 探测默认 5 秒超时，且与调用方的 `AbortSignal` 合并（`AbortSignal.any`）。
- curl 以 `-L --proto-redir =http,https` 跟随重定向：跳转目标同样只允许 HTTP(S)，
  防止一个 http 地址把下载带到 `file://`、`ftp://` 等协议。`=` 不能省，否则 curl 会把
  `http,https` 当成文件名。
- **镜像是第三方中转**：请求内容会经过镜像服务器。文档与 README 都提醒不要用它下载含敏感
  信息的文件；插件无法验证镜像返回的内容是否忠实于源站（这正是第四层字节数校验存在的原因
  之一 —— 镜像返回一个 200 的错误页时，只有校验能拦下；第五层的摘要才是决定性的）。

## 本地持久化：吞吐缓存（`1.3.0` 起，`src/throughput-cache.ts`）

用于「下次按历史吞吐抬档」的本地缓存（并发上限仍是 8，不会更高）。它比进度文件更值得单独
说明，因为**它等于一份「这台机器下过哪些主机」的清单**：

- 键 = **主机名的 sha256 前 32 个十六进制字符 + 端口**。缓存文件名与文件内容里都**没有明文
  域名**；路径不参与分桶（同一站点的不同路径共享带宽，这是缓存能命中的前提）。
- 一条记录只含：最近 5 次吞吐样本、其中位数、当时的**请求**并发数、当时的**实际有效连接数**
  （aria2 摘要的 `CN`）、更新时间。**不含**完整 URL、路径、查询串（因此不含 token 一类凭证）、
  文件名、IP。
- 位置：`$DSH_SMARTDL_THROUGHPUT_DIR`，缺省 `<DSH_HOME>/downloads/throughput`。TTL 24 小时，
  过期条目在下次读取时顺手删除。
- **为什么默认不存明文主机名**：这个用途只需要「同一个主机再次出现时能对上」，哈希完全够用；
  而明文清单一旦落盘，任何能读到该目录的进程、备份或同步盘都能直接得到「你下载过哪些站点」。
  代价是缓存条目无法人工肉眼看出「这条是谁」—— 这个代价是刻意付的。
- **为什么所有读写失败都静默**：缓存是优化，不是功能。目录不可写、文件损坏、记录被手改过
  （形状校验不通过）时一律当作「没有历史」，回落到按文件大小分档；缓存**只用于抬档、不用于
  降档**，所以读取失败不会有任何安全或正确性后果，也不会让下载失败。
- 写入只发生在**成功且通过完整性校验的 aria2 下载**结束时：失败 / 取消 / 超时的样本不写
  （它们的「速度」不代表这台主机的能力），curl 路径也不写（curl 的进度解析只给出百分比、
  没有字节速率可观测，而单连接的样本会把「这台主机多连接能跑多快」稀释掉）。

## 本地持久化：输出路径与产物指纹（`1.4.0` 起，`src/progress.ts`）

`1.4.0` 起，进度记录的两条轨道（轨道一 `ProgressRecord` JSONL、轨道二 `DownloadTaskFile` JSON）
会额外写入三个**可选**字段，用于下载管理器（侧边栏面板）的「在文件管理器中显示」与
「删除记录 / 删除本地文件」：

| 字段 | 内容 | 为什么需要 |
| --- | --- | --- |
| `outPath` | 该次下载**输出文件的绝对路径** | 面板要能定位产物；删除本地文件时必须知道文件在哪 |
| `size` | 完成时的字节数 | 判断「文件还是不是当初下载的那一个」——被替换/截断时**拒绝删除** |
| `fileMtimeMs` | 完成时的修改时间（毫秒） | 同上，作为尺寸之外的第二条诊断信息 |

隐私说明：

- **`outPath` 含本机绝对路径**（通常含用户名，如 `C:\Users\<name>\Downloads\a.zip`）。这三个字段
  **只写进本机进度文件**（`$DSH_DOWNLOAD_PROGRESS_DIR`，缺省 `<DSH_HOME>/downloads/tasks/*.json`；
  与会话进度目录下的 `*.jsonl`），**不随任何网络请求外发** —— 本插件的出站请求只发往被下载的
  URL 与其镜像，从不发送进度数据。
- 可见性与既有进度记录完全一致：它们会被 `download_status` 与 `/api/smartdl.status` 读出来
  返回给**本机会话**里的面板（`outPath` 因此也会出现在工具返回结果与面板上）。会话记录的可
  见性规则与其他 DSH 插件相同。
- 生命周期与既有记录相同：受 `smartdl.cleanup` 的保留窗口管辖，也可以由面板的
  「删除记录」（`POST /api/smartdl.manage` 的 `op:"forget"`）单独清掉。
- 关掉这份记录的方式就是删掉对应记录：`outPath` 只存在于进度文件里，没有别的副本。
- **为什么不做成哈希**：与吞吐缓存不同，这里的目的就是「把文件交给操作系统的文件管理器 / 删除」，
  必须拿得到真实路径，哈希给不出可操作的目标。代价是进度文件里会出现本机路径 —— 这个代价
  在 1.4.0 的下载管理器需求下是必须付的。

## 本地持久化：重试元数据（`1.6.0` 起，`src/tasks.ts`）

`1.6.0` 的下载管理器支持对 `failed` / `cancelled` 的任务原地重试。重试所需的最小信息
写进轨道二任务文件的 `request` 字段：

| 字段 | 内容 | 为什么需要 |
| --- | --- | --- |
| `url` | 原始下载地址 | 重试必须重新请求同一个地址 |
| `output` | 显式输出路径（绝对路径，可选） | 没有它时退回记录里的 `outPath` |
| `sha256` / `checksum` | 调用方给的摘要（可选） | 重试仍要核对同一份内容 |
| `ifExists` | 同名文件策略（可选） | 不因重试而改变覆盖语义 |
| `mirror` | 镜像前缀或 `auto`（可选） | 保持原来的加速方式 |
| `maxBandwidthBytes` / `timeoutMs` | 该条目的限速 / 超时（可选） | 不把用户设过的约束悄悄丢掉 |
| `batchId` | 原批次 ID（可选） | 仅作分组标签 |

**请求头一律不落盘。** `Authorization`、Cookie、`Referer`、User-Agent 与调用方自定义的
`headers` 都不写进 `request`，重试时也**不会重放**。原因很直接：这些值常常是长期凭证，
写进 `~/.dsh/downloads/tasks/*.json` 等于把秘密留在磁盘上，还会被备份工具、同步盘与
其他读该目录的进程看到。代价是受保护地址的重试会失败 —— 这是刻意取舍，不是遗漏；
需要鉴权时请重新调用 `smart_download` 并传 `headers`。

其他边界：

- **`url` 会落盘，可能包含签名查询串**（如 `?X-Amz-Signature=…`、`?token=…`）。它的
  生命周期与进度记录相同：受 `smartdl.cleanup` 保留窗口管辖，也可用 `op:"forget"` 删除；
  删除记录即删除该 URL 元数据，没有别的副本。
- 重试前会重新执行协议白名单（`checkDownloadUrl`）与摘要格式校验；非法值回
  `not-retryable`，不会拿坏数据发请求。
- 旧版本（`1.5.0` 及更早）写的记录没有 `request` 字段，**不可重试**（回 `no-request`）；
  这不是损坏，重下即可。
- `cancel` 只操作**当前 Host 进程内**登记的 `AbortController`；它不写文件、不持久化。
  Host 重启后旧任务本就不存在，取消会如实回 `not-running`。

## 删除本地文件（`1.4.0` 起，`POST /api/smartdl.manage` 的 `op:"delete"`）

**不可逆：删除不进回收站**。本插件是 Node 侧宿主代码，运行时里没有可用的回收站服务
（Electron 的 `shell.trashItem` 不在我们的能力面里），因此 `unlink` 就是永久删除；端点返回值里
带固定文案说明这一点，客户端必须二次确认（显示完整绝对路径与大小）。规则：

- **路径只能来自本插件自己写下的记录**（`outPath`）。请求体只接受 `op` / `taskId` / `confirm` /
  `session`；**载荷里出现任何路径字段都不会被读取**。`taskId` 还要过文件名白名单
  （`[A-Za-z0-9._-]`、字母数字开头、≤64 字符），防止把 `..` / 分隔符拼进记录文件路径。
- `outPath` 必须**是绝对路径**、**已归一化**（`path.normalize(p) === p`，因此不含 `.` / `..`）、
  不含 NUL。
- **只用 `lstat`**（不跟进符号链接）：目标是符号链接 → 拒绝（`is-link`）；是目录 → 拒绝
  （`is-dir`）；既不是普通文件也不是目录/链接 → 拒绝。绝不会递归删除。
- 记录了 `size` 时**必须与磁盘上的当前尺寸一致**：不一致（`changed`）→ 拒绝。这一条挡的是
  「原文件被移走、另一个文件占用了同一个名字」。
- 目标落在本插件自己的进度记录目录内 → 拒绝（那条路属于「删除记录」的职责）。
- 任务仍在运行（记录里状态是 `running`）→ 拒绝删除产物，也保留记录。
- **顺序是硬要求：先删产物、成功后再删记录**。反过来会在产物删除失败时让用户永久失去重试入口。
- 删不掉时**如实分类回报**，绝不假装成功：`gone` / `busy` / `denied` / `is-dir` / `is-link` /
  `changed` / `no-path` / `running`（另带一个非契约的 `errorCode` 供排查）。`1.4.0` 之前的历史记录
  没有 `outPath`（`no-path`）⇒ 面板只提供「删除记录」。
- 「删除记录」（`op:"forget"`）只删本插件自己写的两条记录文件（同样 `lstat` + 只认普通文件），
  **绝不触碰产物**。

## 子进程

- 启动随包 `aria2c`、`PATH` 上的 `aria2c` 或系统 `curl`，均以 `windowsHide: true`
  启动，不弹控制台窗口。
- 参数以数组形式传给 `spawn`，不经 shell，因此 URL 里的字符不会被 shell 解释。
- 取消时先 `SIGTERM`，1 秒内未退出则 `SIGKILL` 兜底；兜底对**所有平台**生效
  （`0.9.0` 之前只对 Windows 生效，POSIX 上进程忽略 `SIGTERM` 会让调用永久挂住）。
- aria2 的 `-o` 只接受文件名、目录用 `-d` 传，避免把路径拼进单个参数。

### `PATH` 上的 aria2 与信任边界

随包子包不可用时（例如 macOS，或镜像源没有同步子包），`getAria2Path()` 会扫描 `PATH`：

- 只接受**普通文件**（`statSync().isFile()`），目录与特殊文件跳过；
- 对候选执行 `aria2c --version`，退出码为 0 才采用；失败或超时则继续找下一个；
- 找不到任何可用候选才回退 `curl`。

**这只是「可执行性检查」，不是哈希或来源验证。** 随包二进制有项目发布前的哈希核对，
`PATH` 上的二进制没有 —— 它属于宿主环境的信任边界。请只使用可信包管理器安装的 aria2，
不要把不可信目录放进 `PATH`。扫描本身不发网络请求，也不读取文件内容。

## 权限清单

| 行为 | 说明 |
| --- | --- |
| 网络出站请求 | 仅 `http` / `https`（**FTP / SFTP / BitTorrent 一律拒绝**）；`HEAD` / `Range` 探测与实际下载；只访问传入的 URL |
| 写入下载文件 | 显式 `output` 路径（调用方可以指定任意可写路径），或按 URL / `Content-Disposition` 推导的单段文件名（落在当前工作目录） |
| 读取进度文件 | `download_status` 与 `/api/smartdl.status` 只读扫描，不写、不联网 |
| 记录输出路径与指纹 | 进度记录里加 `outPath`（绝对路径）/ `size` / `fileMtimeMs`，只落本机（见上方「本地持久化：输出路径与产物指纹」） |
| 记录重试元数据 | 进度记录里加 `request`（URL / 输出路径 / 摘要 / 镜像 / 限速 / 超时），只落本机；**不含任何请求头或凭证**（见上方「本地持久化：重试元数据」） |
| 读取输出文件元数据 | `/api/smartdl.manage` 的 `inspect` / `delete` 对记录里的 `outPath` 做 `lstat`（存在性 / 类型 / 大小 / mtime）；**只读元数据，不读文件内容** |
| 删除下载输出文件 | 仅 `op:"delete"` + `confirm:true`，且只删本插件记录过、逐条通过上述规则的 `outPath`（**不可逆**，不进回收站） |
| 删除进度记录 | 仅针对本插件自己写的两条记录文件（`op:"forget"` / `delete` 的收尾），只认普通文件 |
| 取消下载 | 仅 `op:"cancel"` 且任务在本 Host 进程内正在运行；abort 对应 `AbortController`，子进程按 `SIGTERM` → `SIGKILL` 结束；不写文件、不联网 |
| 重新发起下载 | 仅 `op:"retry"` 且记录状态为 `failed` / `cancelled`；请求信息只来自本插件记录，不读调用方给的 URL / 路径 / 请求头；后台运行，不等下载完成 |
| 写进度文件 | 两条轨道（见 README「进度上报」）；目录不可写时静默跳过，不影响下载 |
| 写吞吐缓存 | `<DSH_HOME>/downloads/throughput/<主机名 sha256 前 32 字符>-<端口>.json`；只存哈希（不含明文域名 / URL / 查询串）；仅在成功的 aria2 下载后写入；写失败静默忽略 |
| 读取磁盘元数据 | 远端声明大小且响应未压缩时，用 `statfs` 查询**目标目录所在文件系统**的可用空间；只读元数据，不读文件内容 |
| 查找 `PATH` 上的 aria2 | 遍历 `PATH` 目录，`statSync` 判断普通文件，并执行 `aria2c --version`（5 秒超时）；仅子包不可用时发生 |
| 子进程 | 随包 / `PATH` 上的 `aria2c` 或系统 `curl`；`windowsHide`；响应 `AbortSignal` |
| 读取环境变量 | 仅 `DSH_PROGRESS_DIR`、`DSH_DOWNLOAD_PROGRESS_DIR`、`DSH_SMARTDL_THROUGHPUT_DIR`、`DSH_HOME`、`DSH_SMARTDL_MIRRORS` |

**不需要**的权限：不读取 DSH 会话内容、不访问凭证或密钥、不修改 DSH 配置（`cordis.patch.yml`
由 DSH 自身在安装时应用）、无遥测与联网上报。

## 已知边界

- **不支持 FTP / SFTP / BitTorrent**（`magnet:` 同样拒绝）。这不是「以后会补」的功能缺口，
  而是「放开白名单后默认路径上没有内容校验」的刻意取舍，理由见上方第一层末尾的表格。
- **没有 `sha256` / `checksum` 时不做任何内容哈希校验。** 远端声明的长度本身也可能是
  错的或恶意的，此时长度校验会通过。真正的内容校验需要摘要，而插件不假设远端会提供 ——
  摘要由调用方从官方文档传进来（第五层）。不传就没有这一层。
- **自动镜像的「同源证明」防不了投毒。** 候选必须长度一致、且原始有 `ETag` 时 `ETag` 也
  一致才会被采用，这挡得住「镜像缓存了旧版本」「返回了错误页」这类无心之失。但 `ETag`
  是镜像**自己声明的**：一个恶意镜像可以照抄原始 ETag 再返回等长但不同的内容，长度与
  ETag 都对得上，字节数校验也拦不住。要防投毒只有调用方提供的摘要（优先 SHA-256 /
  SHA-512）。企业内网请用
  `DSH_SMARTDL_MIRRORS` 把候选限定成自己信任的镜像。
- **`mirror: "auto"` 会把候选镜像地址也探测一遍**（并发 HEAD）。这是自动模式的必要代价，
  且必须显式传 `auto` 才会发生；默认不启用。
- **自定义请求头的凭证会出现在子进程命令行里**（见上方「请求头注入」）。
- **重试不会重放自定义请求头**：这是刻意的安全边界，不是 bug。受保护地址的重试会得到
  服务器原本的 401 / 403，需要重新调用 `smart_download` 并传 `headers`。记录里的 URL
  可能含签名查询串，删除记录即删除该元数据。
- 进度文件里含输出文件名与 URL 推导出的路径，会落在 `.dsh-progress/` 与会话目录下，
  与其他 DSH 插件共享同一套可见性规则。`1.4.0` 起进度文件里还会含**产物绝对路径**
  （`outPath`，通常带用户名），`1.6.0` 起还会含**原始 URL**，口径见上方两节「本地持久化」。
- **删除本地文件不可撤销**：不进回收站（无可用服务）。被删的路径来自本插件的记录而非调用方
  输入，且逐条做绝对路径 / 归一化 / `lstat` 类型 / 尺寸核对后才执行；任何一条不确定就拒绝并如实回报。
- 随包 `aria2c.exe` 未做代码签名，可能触发杀毒软件的启发式告警，见
  [TROUBLESHOOTING.md](./TROUBLESHOOTING.md)。
